## 이 부(15~18강)에서 다루는 것

1~14강은 Claude 앱 안의 브라우저와 Computer Use로 **사람이 지켜보며** 하는 자동화였습니다. 15~18강은 한 걸음 더 나가, 별도 앱인 **Aside AI 브라우저**를 명령줄로 불러 **매일 혼자 도는 업무**로 만든 실제 사례를 정리합니다. 영상 제작, 블로그·SNS 발행, 자료 수집까지 여러 프로젝트에서 실제로 돌고 있는 방식입니다.

Aside의 가장 큰 장점은 **내가 이미 로그인해 둔 브라우저를 그대로 쓴다**는 점입니다. 구글·유튜브 스튜디오·페이스북·학습 사이트처럼 공개 API가 없거나 쓰기 까다로운 곳도, 내 로그인 상태 그대로 스크립트가 다룹니다.

## 두 가지 방식

| | `aside repl` | `aside exec` |
|---|---|---|
| 하는 일 | 내가 쓴 자바스크립트(Playwright 비슷한 문법)를 브라우저에서 실행 | Aside 안의 AI 에이전트에게 말로 일을 맡김 |
| 비용 | **무료** | 에이전트 크레딧 소모 |
| 결과 | 매번 똑같이 동작 | 상황에 맞춰 판단하지만 매번 조금씩 다름 |
| 어울리는 일 | 매일 반복하는 수집·입력·업로드 | 화면이 자주 바뀌거나 판단이 필요한 일 |

**규칙: repl이 기본, exec는 예외.** 매일 도는 일과 읽기만 하는 일은 repl로 옮깁니다. exec는 에이전트의 판단이 꼭 필요할 때만 씁니다(16강의 영상 첫 프레임 지정, 업로드 결과 검증 같은 경우).

> **용어 풀이** CLI = 명령줄 도구. 터미널에서 `aside ...` 로 부르는 프로그램입니다. repl = 코드를 한 덩어리씩 보내 바로 실행하는 창구입니다.

## repl 한 번 써 보기

```bash
aside repl "const p = await openTab('https://example.com'); const s = await snapshot(p, { interactive: true }); console.log(s.tree);"
```

- `openTab(url)` — 새 탭을 열고 페이지가 준비될 때까지 기다립니다.
- `snapshot(page)` — 화면을 **접근성 트리**로 읽어 줍니다. 버튼·입력칸마다 `ref=e12` 같은 번호가 붙습니다.
- `page.locator('e12').click()` — 그 번호로 누릅니다.
- `fetch(url)` — 내 로그인 쿠키를 실은 채 요청합니다. 탭을 열지 않고 문서를 받을 때 씁니다.

Gmail·구글 독스·시트·유튜브처럼 자주 쓰는 사이트는 Aside가 미리 만든 도구가 있습니다. 먼저 확인하세요.

```bash
aside skills list
aside skills show google-gmail
```

## 실제로 만난 함정 다섯 가지

실제 업무 스크립트들이 몇 주 돌면서 기록한 것들입니다. 처음부터 이렇게 짜면 대부분 피합니다.

**1. 한 번 호출은 120초까지.** repl 한 번이 2분을 넘기면 연결이 끊깁니다(`other side closed`). 영상 목록 60개를 한 번에 돌다가 매일 실패한 사례가 있습니다. **8~10개씩 나눠 여러 번 부르세요.**

**2. 업데이트로 문법이 깨질 수 있다.** Aside 업데이트 뒤 `getByRole('button', { name: /정규식/ })` 이 갑자기 "찾을 수 없음"이 된 적이 있습니다. 버튼을 이름 정규식으로 찾는 대신, 페이지 안에서 직접 찾아 누르는 쪽이 튼튼합니다.

```js
await page.evaluate((i) => {
  const bs = [...document.querySelectorAll('main button')].filter(b => /개 영상/.test(b.innerText));
  bs[i].click();
}, 0);
```

**3. 탭은 호출이 끝나면 닫힌다.** repl 한 번에서 연 탭은 그 호출이 끝나면 사라집니다. 여러 단계를 이어 가야 하면 ① 한 호출 안에서 끝까지 하거나 ② repl 프로세스 하나를 계속 열어 두고 명령을 이어 보냅니다(17강 페이스북 사례).

**4. 다운로드는 기다릴 수 없다.** 다운로드 완료 이벤트를 기다리는 기능이 없습니다. 브라우저 기본 다운로드 폴더(`~/Downloads`)에 파일이 생기는지 확인한 뒤 옮깁니다.

**5. 예약 실행에서 `aside` 명령을 못 찾는다.** macOS 예약 실행(launchd)은 PATH가 짧아서 `aside`(보통 `~/.local/bin`)를 못 찾습니다. 몇 주 동안 조용히 실패한 사례가 있습니다. 예약 설정의 PATH에 `~/.local/bin` 을 꼭 넣으세요.

## 안전 규칙 (모든 사례 공통)

- **로그인은 사람이.** 스크립트는 로그인 화면·보안 확인(캡차)을 만나면 멈추고 알립니다. 스스로 로그인하지 않습니다.
- **마지막 발행 버튼은 사람이.** 게시·예약 확정 직전까지만 자동으로 하고, 초안으로 저장한 뒤 사람이 확인해 누릅니다.
- **Aside가 켜져 있고 로그인돼 있어야 한다.** 예약 작업 전에 `open -a Aside` 로 띄우고, `aside memory list` 가 응답하는지 확인하면 안전합니다.
- **파일 쓰기는 세션 폴더 안에서만.** repl 안의 `fs`는 세션의 `artifacts/` 폴더에만 씁니다. 결과는 출력으로 받아 바깥 스크립트(파이썬 등)가 저장합니다.
