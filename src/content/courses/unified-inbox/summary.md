과정 안내 영상 — 8개 강좌를 시작하기 전에

## 이 과정에서 만드는 것

카톡·문자·메일·홈페이지 문의·통화 녹음처럼 **여러 곳으로 흩어진 연락을 한 DB 에 모으고**, 거기서 일정·할 일·미답장·대화 어긋남을 뽑아 **한 화면(보드)** 에 보여 주는 AI 통합 비서예요. 클로드 데스크탑의 Code 탭(또는 터미널의 Claude Code)에게 단계를 하나씩 시키고, 사람은 결정·대조·승인을 해요.

원칙은 하나예요. **수집은 기계가, 판단은 모델이, 바깥으로 쓰는 일(답장·캘린더 등록·발행)은 사람이 승인한 뒤에만** 해요. 이 과정은 자동 답장을 만들지 않아요.

```
카톡(맥 접근성) ─┐
문자(폰 알림)   ─┤
메일            ─┼→ 채널별 원본 DB → 추출(AI) → items DB → 보드 화면
홈페이지 문의   ─┤        │                         │        └→ [등록] 승인 → 캘린더
통화 전사       ─┘        └→ 판정(유형·어긋남) ──────┘
```

## 전체 흐름

**1부 · 준비와 첫 수집**
1. **1강 큰 그림과 사전 결정**: 무엇을 모을지, 외부 AI 로 보낼 범위, 읽음 처리 허용 여부를 먼저 정해요. (35분)
2. **2강 첫 채널 수집기**: 가장 급한 채널 하나만 원본 DB 에 모으고 건수로 확인해요. (50분)
3. **3강 사람 대조로 검증**: 방 하나의 최근 12건을 직접 맞춰 보고 범위를 넓혀요. (35분)

**2부 · 판단과 반영**
4. **4강 판정·추출과 items DB**: 유형 분류, 어긋남 경고, 일정·할 일 후보를 한 표에 모아요. (50분)
5. **5강 캘린더 반영**: 드라이런으로 후보를 같이 보고, 승인한 것만 등록해요. (40분)

**3부 · 화면과 운영**
6. **6강 보드 화면**: 본문 없이 일정·할 일·미답장·경고를 한 화면에, 쓰기 버튼은 승인함으로. (50분)
7. **7강 자동 실행**: 정해진 시각에 수집 → 판정 → 추출 → 캘린더 순서로, 실패하면 멈추기. (40분)
8. **8강 채널 늘리기와 지켜야 할 선**: 문자 → 메일 → 문의 순으로 늘리고, 규칙표로 선을 정해요. (40분)

## 실습 결과물

- 사전 결정표(`inbox/decisions.md`)
- 채널별 원본 DB 1개 이상과 수집 로그(본문 없이 건수·최신 시각만)
- 사람 대조 기록 1회
- items DB 와 캘린더 드라이런 후보 목록
- 읽기 전용 보드 화면 + 승인 버튼
- 다음 날 아침 확인한 자동 실행 로그
- 내 규칙표(`inbox/rules.md`)

카톡 자동화 방식 다섯 갈래(PlayMCP·접근성·매크로·안드로이드·로컬 DB) 비교는 [카카오 개인 계정 자동화 5가지](/lectures/kakao-personal-automation)에서 먼저 볼 수 있어요. 이 과정은 그중 2번 접근성 방식을 실습해요.

## 준비물

- 맥(카톡 접근성 수집 기준. 윈도는 대안만 다뤄요)과 클로드 데스크탑(Code 탭) 또는 Claude Code
- 일정을 올릴 구글 캘린더 계정
- 모을 채널: 맥 카톡, 안드로이드 폰(문자·알림), 메일 계정, 홈페이지 문의 폼 중 지금 쓰는 것
- 선행 권장: [안전·비용·계정](/basics/vibe-safety-money)

## 끝나면 할 수 있는 것

- 흩어진 연락이 원본 DB → items DB → 보드로 흐르는 구조를 설명해요.
- 수집 결과를 사람 대조로 검증하고, 검수 전에는 정확도를 말하지 않아요.
- 캘린더 등록을 승인 경로로만 일어나게 하고 중복을 막아요.
- 읽음 처리·외부 전송 범위·계정 제재 위험을 사용자와 먼저 정하고 지켜요.
