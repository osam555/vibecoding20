> **주의.** 맥 카톡 접근성 수집은 방을 열어서 읽기 때문에 **읽음 처리**가 일어나고, 수집하는 동안 카톡 창이 앞으로 나와요. 1강 결정표에서 허용한 범위만 열어요. 접근성 조작도 자동화라 계정 제재 위험이 있어요. 처음에는 방 3개로만 시험해요.

## 채널별로 어떻게 읽나요

| 채널 | 권장 경로 | 한계 |
|---|---|---|
| 카톡(맥) | OS 손쉬운 사용(접근성)으로 채팅 탭 읽기 | 읽음 처리, 창이 앞으로 나옴, 날짜는 근사 |
| 카톡(보조) | 안드로이드 알림 캡처 | 내가 보낸 말, 알림 끈 방은 없음 |
| 문자 | 안드로이드 알림 캡처 + 문자 백업 | 금융 문자 본문은 저장하지 않음 |
| 메일 | 메일 API·커넥터, 없으면 AI 브라우저 | 본문 전체 저장은 피함 |
| 홈페이지 문의 | 폼 저장소 API, 없으면 관리 화면 | 이름·연락처는 따로 보관 |
| 통화 | 녹음 앱의 전사 텍스트 파일 | 화자 구분 필요 |

이번 강에서는 **하나만** 해요. 아래는 맥 카톡 예시예요. 다른 채널도 원본 DB 규칙은 같아요.

## 원본 DB 규칙

- 채널마다 DB 하나: `kakao.sqlite`, `sms.sqlite`, `mail.sqlite`.
- 공통 열: `room, sent_at(YYYY-MM-DDTHH:MM), sender, text, src`.
- 내가 보낸 메시지는 `sender='나'` 로 통일해요. 미답장·어긋남 판단의 기준이에요.
- `UNIQUE(room, sent_at, sender, text)` 로 중복을 막아요. 몇 번을 다시 돌려도 같은 결과예요.
- 로그와 보고에는 **본문을 찍지 않아요.** 건수·방 수·최신 시각만.

## 따라하기 (맥 카톡)

1. 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 **수집을 실행할 앱**(터미널 또는 클로드 데스크탑)에 권한을 줘요. 권한 설정은 사람이 직접 해요.
2. 클로드에게 시켜요.

> 맥 카톡 채팅 탭(1:1·단톡, 오픈채팅 제외)을 손쉬운 사용 접근성으로 읽는 수집기를 만들어줘. AppleScript 로 행을 도는 방식 말고 Swift 로 요소를 읽어. 탐색에는 시간 상한과 개수 상한을 꼭 둬. 결과는 `db/kakao.sqlite` 의 `messages(room, sent_at, sender, text, src='ax')` 에 넣고, 내가 보낸 말은 sender 를 '나'로 해. `UNIQUE(room, sent_at, sender, text)` 로 중복을 막아. 안 읽은 방은 열지 말고, `--limit 3` 으로 방 3개만 시험해. 출력에는 본문 없이 방 수·새 메시지 수·실패·일부만 읽음·남은 창 수만 보여줘.

3. 시험 실행 결과를 봐요. 예: `방 3 · 새 메시지 41 · 실패 0 · 일부만 읽음 1 · 남은 창 1`.

## 확인 방법

- 다시 한 번 돌렸을 때 **새 메시지가 0** 이면 중복 방지가 된 거예요.
- 끝나고 카톡에 **메인 창만** 남았는지 봐요. 열린 방 창이 남으면 다음 실행이 꼬여요.
- `일부만 읽음` 이 나온 큰 방은 최신부터 저장된 것이라 과거 대화가 빠졌을 수 있어요.

## 자주 만나는 함정

- 수집 중 새 메시지로 목록이 움직이면 방을 못 찾아요. 실패가 아니라 다음에 다시 시도할 방이에요.
- 날짜 구분선이 접근성으로 안 읽혀서, 날짜는 목록 날짜에서 거꾸로 계산한 **근사값**이에요.
- 사진만 있는 메시지는 저장하지 않아요.
- 같은 카톡을 쓰는 다른 자동화와 시간이 겹치지 않게 해요.

::: practice
- [ ] 손쉬운 사용 권한을 직접 줬다
- [ ] `--limit 3` 시험 결과를 건수로만 확인했다
- [ ] 두 번째 실행에서 새 메시지가 0 인 것을 봤다
- [ ] 메인 창만 남았는지 확인했다
:::
