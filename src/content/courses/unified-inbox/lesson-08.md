> **주의.** 채널을 늘릴 때마다 **외부 AI 로 보낼 범위를 다시 정해요.** 카톡 업무방만 보내기로 했다고 메일 전체를 보내도 되는 건 아니에요. 범위가 바뀌면 다시 묻고 나서 보내요.

## 하나씩 늘리는 순서

한 채널을 붙일 때마다 2강(수집) → 3강(사람 대조) → 4강(추출)을 다시 짧게 돌아요.

| 순서 | 채널 | 붙일 때 주의 |
|---|---|---|
| 1 | 문자 | 안드로이드 알림 캡처 + 문자 백업. **금융·인증 문자 본문은 저장하지 않아요** |
| 2 | 메일 | 메일 API·커넥터. 헤더·제목만 저장하고 후보가 된 메일만 본문에서 추출 |
| 3 | 홈페이지 문의 | 폼 저장소 API. 이름·연락처는 items 에 넣지 않고 원본 문서 id·링크만 |
| 4 | 통화 | 녹음 앱 전사 파일 폴더 감시. 화자 구분이 필요해요 |

메일 연결, 폼 관리자 로그인 같은 **계정 연결과 권한 동의는 사람이 직접** 해요.

## 클로드에게 이렇게 시켜요

> 메일 채널을 붙여줘. 원본은 `db/mail.sqlite` 에 카톡과 같은 공통 열(room=보낸 쪽, sent_at, sender, text, src)로 저장하되 text 에는 제목만 넣어. 내가 보낸 메일은 sender='나'. 추출 단계에서는 후보가 된 메일만 본문을 읽어 일정·할 일을 뽑고 본문은 저장하지 마. 외부로 보내는 범위는 `inbox/decisions.md` 의 메일 항목을 따르고, 없으면 멈추고 나한테 물어봐.

## 규칙표 만들기

> `inbox/rules.md` 에 내 통합 비서의 규칙표를 만들어줘. 항목은 채널별 외부 전송 범위, 읽음 처리 허용 여부, 승인이 필요한 쓰기(캘린더·답장), 자동 실행 시각과 빈도, 키·토큰 보관 위치(키체인이나 환경변수), 보드를 둘 곳, 멈추는 방법이야. 빈칸은 내가 채울게.

## 지켜야 할 선

- **자동 답장·세금계산서 발행·업무 시스템 입력은 이 과정 범위 밖**이에요. 하려면 건별 승인 단계를 따로 설계해요.
- "계정 정지 위험 없음"이라고 말하지 않아요. 접근성 조작도 자동화라 빈도를 낮게 둬요.
- 외부로 보내는 범위는 정한 그대로 지켜요. 바뀌면 다시 물어요.
- 키·토큰은 키체인이나 환경변수에 두고, 화면에 출력하거나 저장소에 커밋하지 않아요.
- 다른 사람의 대화가 들어 있어요. 보드와 로그에 본문을 남기지 않아요.

## 완료 기준

- [ ] 채널별 최신 수집 시각이 하루 안이다
- [ ] 사람 대조를 1회 이상 통과했다
- [ ] 캘린더 등록이 승인 경로로만 일어나고 중복이 없다
- [ ] 보드에 본문이 노출되지 않는다
- [ ] 다음 날 자동 실행 로그가 성공이다

::: practice
- [ ] 두 번째 채널을 붙이고 사람 대조를 다시 했다
- [ ] `inbox/rules.md` 빈칸을 채웠다
- [ ] 완료 기준 다섯 줄을 하나씩 확인했다
:::
