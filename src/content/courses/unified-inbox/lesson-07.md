> **주의.** 자동 실행 중에는 카톡 창이 앞으로 나와요. 1강에서 정한 **PC 를 쓰지 않는 시간**에만 돌려요. 자동이라도 캘린더 실제 등록은 승인 경로로만 해요. 빈도는 하루 한두 번처럼 낮게 둬요.

## 순서와 규칙

```
수집 → 판정 → 추출 → 캘린더 후보(드라이런)
앞 단계가 실패하면 뒤 단계는 돌리지 않는다
```

- **두 시각**: 1차 시각 + 실패했을 때를 위한 재시도 시각. 성공하면 날짜가 적힌 성공 표식 파일을 남겨, 재시도는 표식을 보고 바로 끝나요.
- **권한**: 접근성이 필요한 작업은 손쉬운 사용 권한을 받은 앱으로 실행해요. 터미널에 준 권한은 launchd 로 이어지지 않아요.
- **화면 조작은 앞에**: 긴 작업 뒤쪽에 카톡 화면 조작을 넣지 않아요. 언제 닿을지 몰라 내가 일하는 중에 창이 뜰 수 있어요.
- **잠금·잠자기**: 화면이 잠겨 있으면 접근성 조작이 실패할 수 있어요. 실패를 로그와 보드에 남겨요.
- **다른 자동화와 겹침**: 같은 카톡을 쓰는 다른 자동화가 있으면 잠금 파일로 시간을 나눠요.

## 클로드에게 이렇게 시켜요

> 수집 → 판정 → 추출 → 캘린더 드라이런을 순서대로 돌리는 실행 스크립트를 만들고, 맥 launchd 의 StartCalendarInterval 로 매일 새벽 1차 시각과 재시도 시각 두 개를 등록해줘. 각 단계가 실패하면 뒤를 멈추고, 전부 성공하면 오늘 날짜 성공 표식 파일을 남겨. 재시도는 표식이 있으면 바로 끝내. 로그에는 단계별 성공/실패와 건수만 남기고 본문은 남기지 마. 같은 카톡을 쓰는 다른 작업과 겹치지 않게 잠금 파일도 둬. 등록 전에 plist 내용을 먼저 보여줘.

## 확인 방법

- 등록 전에 plist 를 읽고 시각과 실행 앱이 맞는지 봐요.
- **다음 날 아침** 로그를 열어 네 단계가 모두 성공인지, 성공 표식이 생겼는지 봐요.
- 보드에서 채널별 최신 수집 시각이 하루 안인지 봐요.
- 실패했다면 로그의 실패 단계부터 클로드에게 보여 줘요(본문 없이).

::: practice
- [ ] plist 를 읽고 시각과 실행 앱을 확인한 뒤 등록했다
- [ ] 다음 날 로그로 첫 자동 실행 성공을 확인했다
- [ ] 보드의 최신 수집 시각이 하루 안인 것을 봤다
:::
