> **주의.** 보드에는 대화 **본문을 보여 주지 않고** 원본으로 가는 링크만 둬요. 보드는 내 맥이나 사내망(VPN), 또는 로그인 뒤에만 둬요. 메일·카톡 내용을 공개 호스팅에 올리지 않아요.

## 한 화면에 들어갈 것 (모바일 우선)

1. **오늘·이번 주 일정**: 캘린더 일정 + 아직 등록 안 된 후보(「후보」 배지)
2. **출처별 할 일**: 카톡·문자·메일·문의·통화 열, 마감 임박 순
3. **미답장·확인 필요**: 상대가 마지막으로 말하고 내 답이 24시간 없는 방, 새 문의
4. **어긋남 경고**: 판정 0.7 이상만, 「참고」 배지
5. **버튼**: [등록] · [무시] · [완료]

미답장은 원본 DB 의 `sender='나'` 덕분에 계산돼요. 2강에서 내 말을 '나'로 통일한 이유예요.

## 구조

- 수집·추출·DB 는 지금 자동화 폴더에 두고, **화면만 따로** 만들어요.
- 화면은 items DB 를 읽기만 해요. 버튼은 바로 쓰지 않고 **승인함**(대기 목록)에 넣고, 사람이 확인하면 5강 등록 스크립트가 처리해요.

## 클로드에게 이렇게 시켜요

> items DB 를 읽는 보드 화면을 만들어줘. 내 맥에서만 열리게 localhost 로 띄워. 섹션은 오늘·이번 주 일정(후보 배지 포함), 출처별 할 일(마감 임박 순), 미답장·확인 필요(상대가 마지막이고 24시간 내 내 답 없음), 어긋남 경고(0.7 이상, 참고 배지)야. 본문은 절대 보여주지 말고 제목·근거 짧게·원본 링크만 보여줘. 처음에는 읽기 전용으로 만들고, 다 보이면 그다음에 등록·무시·완료 버튼을 승인함에 넣는 방식으로 추가해줘. 폰 화면 폭에서 먼저 보기 좋게.

## 확인 방법

- 폰 폭으로 줄여도 가로 스크롤 없이 읽혀요.
- 화면 어디에도 대화 본문이 없어요. 페이지 소스를 열어 본문 문장이 들어 있지 않은지 한 번 더 봐요.
- [등록] 을 눌러도 바로 캘린더에 생기지 않고 승인함에 쌓여요.
- [무시] 한 항목이 다음 추출에서 다시 생기지 않아요.

::: practice
- [ ] 읽기 전용 보드를 띄우고 다섯 섹션을 확인했다
- [ ] 본문이 노출되지 않음을 확인했다
- [ ] 버튼이 승인함을 거치는지 확인했다
:::
