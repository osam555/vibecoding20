> **먼저 알아둘 것.** 이 과정은 공식 API 가 없는 채널(특히 카톡)을 **화면 접근성·알림 같은 비공식 자동화**로 읽어요. 서비스 약관에 어긋날 수 있고, 계정 이용 제한이 걸릴 수 있어요. 제재 여부와 기준은 각 서비스가 정해서 우리가 통제할 수 없어요. "위험 없다"고 말할 수 있는 방법은 없고, 빈도를 낮추고 범위를 좁혀 **위험을 줄일 수만** 있어요.

## 이런 일을 줄이고 싶을 때

카톡에서 "목요일 3시에 뵐게요", 메일로 온 견적 요청, 홈페이지 문의 폼에 들어온 상담 신청, 통화 중에 약속한 자료 발송. 연락이 다섯 곳에 흩어지면 하나씩은 꼭 놓쳐요. 통합 비서는 이걸 **한 DB 에 모으고, 일정·할 일만 뽑아 한 화면**에 보여 줘요.

## 구조 한 장

```
채널별 수집기 → 채널별 원본 DB(kakao.sqlite, mail.sqlite …)
  → 판정(유형·어긋남, 선택) → 추출(일정·할 일 후보)
  → items DB → 보드 화면 → [등록] 승인 → 캘린더
```

| 단계 | 누가 하나 | 바깥으로 나가나 |
|---|---|---|
| 수집 | 기계(스크립트) | 아니요. 내 컴퓨터 안에만 |
| 판정·추출 | AI 모델 | 정한 범위만 외부 AI 로 |
| 캘린더 등록·답장 | **사람이 승인한 뒤** | 예 |

이 과정은 **자동 답장, 세금계산서 발행, 업무 시스템 입력을 만들지 않아요.** 하고 싶다면 건별 승인 단계를 따로 설계해야 해요.

## 돌리기 전에 정할 여섯 가지

1. **쓰는 채널**: 카톡(맥/윈도), 문자(안드로이드/아이폰), 메일 계정 수, 홈페이지 문의 폼 유무, 통화 녹음 앱.
2. **캘린더**: 일정을 올릴 캘린더와 계정.
3. **외부 AI 로 보낼 범위**: 업무방만인지, 가족·개인 대화도 되는지. 전화번호·계좌 같은 걸 가릴지.
4. **카톡 읽음 처리**: 맥 접근성 수집은 방을 열어서 읽어요. 열면 안 읽은 메시지가 **읽음으로 바뀌고 상대에게도 표시**돼요. 허용할지, 이미 읽은 방만 볼지 정해요.
5. **보드를 볼 곳**: 내 맥에서만, 사내망에서, 폰에서.
6. **자동 실행 시각**: 수집할 때 카톡 창이 앞으로 나와요. PC 를 쓰지 않는 시간으로 정해요.

**답이 정해지기 전에는 수집기를 돌리지 않아요.**

## 클로드에게 이렇게 시켜요

> 여러 채널 연락을 한곳에 모으는 통합 비서를 만들려고 해. `inbox/decisions.md` 를 만들어서 쓰는 채널, 캘린더 계정, 외부 AI 로 보낼 범위, 카톡 읽음 처리 허용 여부, 보드를 볼 곳, 자동 실행 시각을 내가 채울 수 있는 빈칸 표로 정리해줘. 내 실제 대화나 계정 정보는 아직 읽지 마.

터미널로도 할 수 있어요. 같은 문장을 Claude Code 에 입력해요.

## 확인 방법

- `inbox/decisions.md` 에 여섯 칸이 모두 채워졌다.
- "외부 AI 로 보낼 범위" 칸에 방·계정 이름 대신 **기준**(예: "업무 접두어가 붙은 방")이 적혀 있다.

::: practice
- [ ] 위험 안내를 읽고 내가 감수할 위험을 세 줄로 적었다

- [ ] 처음 모을 채널 하나를 골랐다(가장 자주 놓치는 곳)
