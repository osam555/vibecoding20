> **주의.** 이 강부터 대화가 **외부 AI 로 나가요.** 1강 결정표의 "외부 AI 로 보낼 범위"만 보내요. 범위가 바뀌면 다시 정하고 나서 보내요.

## 1. 빠른 분류(선택)

판정 전용 모델로 메시지를 여섯 가지로 나눠요: 잡담·문의·할 일·일정·세금계산서·오류. 12건씩 묶어 보내면 빠르고 싸요.

**대화 어긋남**도 찾아요. 방별 최근 12건에서 수량·날짜·시각·금액이 앞서 합의한 것과 다른데 정정이 없는 경우예요.

가상 예시:

```
상대: 그럼 목요일 오후 3시에 뵙겠습니다
나:   네, 화요일 3시에 갈게요
```

→ 합의는 목요일인데 내 답은 화요일. 정정이 없으면 「어긋남 · 참고」로 띄워요.

보낼 때 지킬 것:
- 방 이름·사람 이름은 빼고 `me/other` 와 본문만 보내요.
- 전화번호·계좌·이메일·주민번호는 가려요.
- 결과는 기록만 하고 보드에 **「참고」** 로만 띄워요. 사람이 실제 대화로 검수하기 전에는 정확도를 주장하지 않아요.

## 2. 일정·할 일 추출

- 입력: 최근 1~2일 원본. 대상은 정한 규칙의 방(예: 업무 접두어) + **내가 말한 방**.
- 출력: `title, due, who, kind(약속·마감·요청·확인), evidence(짧은 근거), confidence, src_kind, src_ref`.
- 새 자료가 없으면 건너뛰어요(건수·최신 시각을 비교). 같은 대화를 매번 다시 보내지 않아 비용이 줄어요.

## 3. items DB

```sql
CREATE TABLE items(
  id INTEGER PRIMARY KEY, k TEXT UNIQUE, created_at TEXT,
  src_kind TEXT, src_ref TEXT, title TEXT, due TEXT, who TEXT,
  kind TEXT, evidence TEXT, confidence REAL,
  status TEXT DEFAULT 'open',      -- open | done | dismissed
  category TEXT, cal_event_id TEXT, cal_registered_at TEXT);
```

- `src_ref` 는 원본으로 돌아가는 열쇠예요(예: `kakao:<방>#12`, 메일 id, 문의 문서 id).
- 중복은 (출처, 제목) 해시 + 제목 유사도·due 로 막아요.
- 사람이 **무시(dismissed)** 한 항목은 다시 만들지 않아요.

## 클로드에게 이렇게 시켜요

> `db/items.sqlite` 에 위 items 표를 만들고, 원본 DB 에서 일정·할 일 후보를 뽑는 추출기를 만들어줘. 대상은 `inbox/decisions.md` 의 외부 전송 범위에 맞는 방과 최근 14일 안에 내가 말한 방만이야. 보낼 때 방 이름·사람 이름은 빼고 전화·계좌·이메일은 가려. 새 자료가 없으면 건너뛰고, dismissed 항목은 다시 만들지 마. 먼저 `--dry-run` 으로 저장 없이 후보만 표로 보여줘(본문 대신 evidence 짧게).

## 확인 방법

- 드라이런 후보를 보고 "실제로 할 일인가"를 한 줄씩 표시해요.
- 같은 명령을 바로 다시 돌렸을 때 "새 자료 없음, 건너뜀"이 나오면 비용 절약이 되는 거예요.
- 어긋남 경고는 「참고」 배지로만 저장됐는지 봐요.
